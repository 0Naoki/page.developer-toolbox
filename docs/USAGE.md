## 共通の操作

コピー中は「コピー中…」、成功すると「コピーしました」と表示します。ブラウザの権限などで失敗した場合はエラーを表示し、同じボタンで再試行できます。コピー対象が変わると、前の操作の完了表示は引き継ぎません。

`Ctrl+K`（Mac は `⌘K`）でコマンドパレットを開き、ツールを検索できます。

ツール画面の「お気に入り」を押すと、サイドバーとトップページの先頭に固定できます。サイドバーの「テーマ」では、OS の設定に従う「自動」と、ライト・ダークを切り替えられます。どちらも表示設定として localStorage に保存し、開いている別のタブにも反映します。

## 保存・消去・編集履歴

入力は sessionStorage（タブごと）にだけ保持し、localStorage には保存しません。タブを閉じると消え、新しいタブには引き継がれません。表示設定（テーマ・お気に入り・インデント幅など）は localStorage に保存します。機密になり得る値を扱う JWTデコーダー（トークン・検証用の鍵）・ハッシュ生成（入力・HMAC の鍵・照合する値）・パスワード生成（生成したパスワード）・UUID / ULID（解析する値）・証明書デコーダーの入力は、sessionStorage にも保存しません（再読み込みすると消えます）。ブラウザのセッション復元などの制約は [SECURITY.md](../SECURITY.md) を参照してください。

JWTデコーダーのヘッダ・ペイロード、Base64 のデコード結果、CSV から変換した JSON は、「JSON整形で開く」で JSON整形の入力として開けます。値はタブ内のメモリだけで渡し、URL には載せません。開いた後は JSON整形の入力として、このタブ（sessionStorage）に保存されます。JWT のペイロードなども、タブを閉じるか全消去するまで残ります。

保存容量超過などで入力を保存できなかった場合は、画面上部に未保存の警告を表示します。入力はその画面のメモリ内に保持し、「未保存の入力をコピー」「未保存の入力を保存」で全文を退避できます。「保存を再試行」や次の入力編集で保存に成功すると警告が消えます。再読み込み・画面移動・タブを閉じる前に退避してください。

以前の版で「入力の保存対象」に選んで localStorage に保存した入力は、起動時に localStorage から消します（今の版の入力としては読みません）。

「保存データをすべて消去」は、同じサイトで開いている別タブにも消去を通知します。

- 消去を実行したタブがこのアプリの localStorage と自分の sessionStorage を消し、通知を受けた各タブは自分の sessionStorage を消します。どのタブも再読み込みしてメモリ内の入力・鍵・編集履歴を破棄します。
- 消去に失敗したタブではツール画面を閉じ、再試行を表示します。再試行ではタブ内の削除をやり直し、共有領域の削除状況を確認します。
- 共有領域の消去を確認できない場合は、「現在の保存データをすべて消去」から新しい全消去を実行できます。確認画面で同意すると、前回の消去後に別タブで保存した内容も含めて消去します。
- 消去したときに別のページへ移動していたタブも、このアプリへ戻ったときに、消去より前の入力を捨てます。
- タブ間通知に入力内容は含まれません。

JSON整形・CSV変換・文字数画面の大きな入力欄は、Undo・Redo（キー操作・ボタン・ブラウザの編集メニュー）を部品の編集履歴で行い、5万文字を超える貼り付けも元に戻せます。CSV変換・文字数画面では、CRLF・CR・LFの元表記も復元します。履歴はメモリ内だけに最大100操作・合計800万UTF-16単位まで保持し、画面移動・再読み込み・ファイルやサンプルへの置き換えで破棄します。Enterは通常LFを追加しますが、直前のCRと結合して改行が減る場合はCRまたはCRLFを追加します。

## 各ツールの入力上限

### 単位

文字列の長さはUTF-16単位です。絵文字などは1文字が2単位になる場合があり、ファイルのバイト数や画面上の文字数とは異なります。ファイルの大きさは、MBを100万バイト、MiBを1,048,576バイト（1024×1024）として書き分けます。画面の表示も同じで、1024を基準にした値は KiB・MiB と表示します。

大きくなり得る入力欄（JSON・CSV・文字数・差分・Base64・ハッシュ・正規表現のテスト文字列と置換文字列・JWT のトークンと公開鍵・証明書・サブネットの一覧・営業日の独自休日）は、50,000単位を超えると先頭だけを表示します。計算・コピー・保存には全文を使い、「全文を編集」で全文を表示・編集できます。入力欄からの直接のコピーは表示部分だけなので、全文は「入力全文をコピー」を使ってください。

上限のある大きな入力欄は、欄の下に「今の長さ / 上限」をUTF-16単位で表示します（表示は「文字」）。上限は下の表の値と同じです。テキスト差分は2つの入力の合計が上限のため、欄ごとには表示しません。

## ツール別の説明

### Base64の入力

Base64・Base64URLのデコードでは、空白・改行、両形式の記号の混在、末尾のパディングの完全省略を許容します。
`YQ==` と `YQ` は、どちらも `a` に復号します。
`=` を書く場合は、空白を除いた全体を4文字の単位にそろえ、末尾の1〜2個だけにします。
`YQ=`・`YQ===`・`YWJj=`・`===` はエラーです。余分な `=` を削除したり、欠けた `=` だけを補ったりはしません。
この扱いは通常入力と、Base64本文を持つdata: URIで共通です。

PEMの本文でもパディングの扱いは同じですが、Base64URLの記号は受け付けません。
JWTは内容を表示できても、署名検証では空白・パディングのない正規のBase64URLが必要です。
HMAC鍵のBase64指定でも不正なパディングは拒否します。UTF-8指定では、入力した文字をそのまま鍵として扱います。
空白だけのUTF-8鍵も入力値として検証します。空文字と、Base64指定・公開鍵の空白だけの入力は未入力として扱います。

### UUID・ULID

生成は UUID v4・UUID v7・ULID に対応します。UUID の解析には、ハイフン付き36文字・ハイフンなし32文字と、それぞれを組の波括弧で囲んだ形式を使えます。片側だけの括弧や一部だけのハイフンは、欠損した入力として拒否します。ULID は26文字で、大文字小文字を区別しません。

生成日時は RFC バリアントの UUID v1・v6・v7 と ULID から取り出します。v1・v6 は100ナノ秒単位の時刻をミリ秒へ切り捨てて表示します。RFC の v3・v4・v5 は時刻を含みません。v2・v8・ほかのバージョンやバリアントは「時刻解析には未対応」と表示し、時刻がないとは断定しません。

### JWT・証明書の判定の読み方

JWT のデコード、時刻クレームの判定、署名の検証はそれぞれ別の処理です。「署名は正しい」は入力した鍵で署名が一致したことを示します。発行者や利用対象（iss・aud など）が利用先の要件に合うかは、利用先で確認する必要があります。JWE はヘッダの表示だけに対応し、復号しません。

証明書・CSR の署名検証は、提示された公開鍵との一致を確かめます。有効期限は別に表示します。チェーンの順番の確認は発行者の名前・鍵識別子による候補の照合であり、信頼するルートまでのパス検証や失効確認（OCSP・CRL）は行いません。自己発行（発行者と主体の名前が同じ）と自己署名（自身の鍵で署名を検証できる）は区別します。

証明書の有効期間の GeneralizedTime に小数部がある場合（`20500101000000.5Z` など）は、日時を丸めずに読み込みエラーにします。小数部を含む証明書日時は [RFC 5280 §4.1.2.5.2](https://www.rfc-editor.org/rfc/rfc5280.html#section-4.1.2.5.2) に準拠しません。

ブラウザが扱えないアルゴリズムや鍵では検証できません。「検証できない」と「署名が一致しない」は区別して確認してください。

### 文字数・バイト数と不可視文字

行ごとの長さの上限は、空欄または0〜9,007,199,254,740,991の整数です。範囲外の値で行を判定せず、再読み込み時は最後に保存した有効な値を使います。

「文字数・バイト数」は「文字数」「不可視文字」「桁あふれ」の表示を切り替えて使います。入力は共通で、切り替えても入力・測定設定・表示ページを保持します。選んだ表示はブラウザに記憶し、「不可視文字のサンプル」は不可視文字の表示を開きます。

不可視文字検査は、貼り付け時のCRLF・LF・CRを保持し、通常の編集では変更していない範囲の改行を保ちます。貼り付けの境界で単独のCRとLFが結合する場合は、改行数を保つため境界の表記を調整します。OSやコピー元が改行を変える場合があるため、元ファイルの正確な改行・BOMはUTF-8ファイルを読み込んで確認してください。不正なUTF-8はエラーになります。

文字は自動削除しません。ZWJや異体字セレクタなど、正しい絵文字・多言語表記に必要な文字も検出します。行・列は1始まりで、列はコードポイント単位、行の区切りはCRLF・LF・CRです。UTF-16位置は0始まりです。通常の半角・全角スペースと改行は種類別集計に表示し、位置一覧には含めません。

### CSV変換

JSONからCSVにするとき、実際に出力する見出しとセルに対になっていないサロゲートがある場合は、CSVの行・列を示してエラーにします。たとえば `[{"value":"\ud800"}]` は復号後の値をUTF-8で保存できないため拒否します。正しい絵文字、文字列としての `\\ud800`、入れ子のJSON内でエスケープのまま残る値は出力できます。見出しを出力しない場合、出力されない項目名は検査対象にしません。

「入れ替え」は、変換結果が逆方向の入力上限以内の場合に使えます。上限を超える結果もコピー・保存できます。

- **ファイルの読み込み**では、選んだ文字コードとして不正なバイトを検出するとエラーを表示し、既存の入力を保持します。文字コードを変更してから、ファイルを選び直してください。
- **数式インジェクション対策**（既定オン）は、`=` `+` `-` `@`（全角の `＝` `＋` `－` `＠` を含む）、タブ、改行で始まる文字列の先頭に `'` を付けます。ただし `-5`・`+1.5`・`-1.5e3`・`-.5` のように半角の数値として読める値は、Excel でも数式にならないためそのまま書きます（全角の `－5` は対象です）。CSVをExcel以外のシステムに取り込む場合は、必要に応じてオフにしてください。

### UTF-8に変換できない文字

JavaScriptの文字列には、UTF-8で表せない「対になっていないサロゲート」が入ることがあります。ツールの目的に応じて次のように扱います。

| 対象 | 扱い |
|---|---|
| JSONからCSVへの変換 | 復号後の出力セル・見出しを検査し、文字が保存時に置き換わる出力を拒否する |
| Base64のUTF-8エンコード・ハッシュのテキスト入力 | U+FFFD（�）に置き換えて処理し、警告を表示する |
| HMAC・JWTのUTF-8の秘密鍵 | 別の鍵への置き換えを避けるため拒否する |

### テキスト差分・正規表現

- **テキスト差分**は、貼り付けで受け取ったCRLF・LF・CRを入力内に保持します。比較と画面の表示では改行の種類の違いを無視します。コピーするunified形式では、`patch` や `git apply` で使えるようにCRLFとLFを保持し、CRだけの改行はLFとして出力します。「空白を無視」「大文字小文字を無視」で一致とみなした行は、変更前の行を共通行として出力するため、変更後の側の空白・大文字小文字の違いはコピーした差分に含まれません。
- **テキスト差分**は、片方にしかない行を除いて比較します。共通の行の順番が大きく異なるテキストでは2秒で差分探索を打ち切り、残りを「まとめて削除・追加」として表示します（内容は正しく、最小の差分ではない旨を画面に表示します）。
- **正規表現**はJavaScriptの構文です。置換はすべてのマッチに適用します。置換結果が上限を超える場合や、500マッチを超えて1秒以上かかる場合は、不完全な置換結果をコピーさせません。

### サブネット

集約・重複チェック・VLSMの一覧は、CRLF・LF・単独CRのどれも改行として扱い、混在している場合も元の行番号を使います。

#### クラウドの予約アドレスとサイズの案内

「AWS・Azure の予約（5アドレス）を除く」は、先頭4つと末尾1つを除いた範囲を計算する設定です。サブネットを実際に作成できるかは、サービスごとの条件やVPC・VNetの構成にも依存します。サイズの案内が対象外でも、指定した範囲の計算結果は表示します。VLSMのクラウド設定は、従来どおりAWSの最小サイズに合わせて /28 より小さくしません。

| サービス | IPv4 のサイズ | IPv6 のサイズ | 参照元 |

### 日付・時刻

和暦の年齢で基準日を空欄にした場合は、日本時間の日付変更とタブへの復帰で「今日」を更新します。明示した基準日や、営業日計算に入力した日付は自動で書き換えません。

- **祝日**は「国民の祝日に関する法律」の規則から計算しています（1980〜2099年）。春分・秋分の日は近似式による値で、正式には前年2月の官報で公表されます。将来の法改正や特例による移動は反映されないため、内閣府の公表データと定期的に照合してください（テストでは2019〜2021年と、内閣府が公表済みの2026・2027年を検証しています）。
- **和暦**は明治6年（1873年、グレゴリオ暦の採用）以降に対応しています。
  西暦9999年まで変換でき、令和100年など3桁以上の元号年も入力できます。
- **UNIX時間変換**は既定で整数部の桁数から単位を判定します。符号と先頭の0を除き、12桁以下は秒、13〜15桁はミリ秒、16〜18桁はマイクロ秒、19桁以上はナノ秒です。短いミリ秒値などは単位を指定できます。ミリ秒未満は0の方向へ切り捨てます。秒を含む歴史的なオフセットは `+09:18:59` のように表示し、日時入力でも受け付けます。
  - 単一エポック入力には文字数の上限を設けていません。先頭の0を除いて単位を判断し、小数部やマイクロ秒・ナノ秒のミリ秒未満の桁を切り捨ててから、日時の有効範囲を確認します。範囲外の長い数値もエラーとして扱い、入力を変えると再計算できます。相対時間は時計に合わせて更新し、固定した入力の日時は変わりません。
- 日時入力は ISO8601 の符号付き6桁の年も受け付けます。
  - たとえば `+010000-01-01T00:00:00.000Z` や `-000001-01-01T00:00:00.000Z` は、ISO8601の出力から読み戻せます。
  - 日時はブラウザの Date の有効範囲（エポックから±1億日）に限ります。`-000000` は無効で、西暦0年は `0000` と書きます。
  - 表示も、紀元前（`-000001` など）と10000年以降（`+010000` など）はこの拡張年の形で出すため、オフセット付きの表示をコピーして日時入力に貼り付けても同じ日時になります。
  - 日時の差は、範囲の両端どうしでもミリ秒まで丸めずに表示します。
  - 各タイムゾーンでの表示は、1秒未満の端数がある時刻ならミリ秒まで出し、端数がなくてもミリ秒単位のエポック時間や小数部を書いた入力なら「.000」まで出します（一括変換も同じ決め方です）。
- **UNIX時間の一括変換**は先頭の0を含む整数部が10桁なら秒、13桁ならミリ秒、16桁ならマイクロ秒、19桁ならナノ秒として扱います。符号と小数部は桁数に含めません。
- **UNIX時間の期間計算**は、各項を整数として合算してから日付の計算に渡します。合算後の年・月・日・経過ミリ秒はそれぞれ±9,007,199,254,740,991以内に限り、計算した日時もブラウザの日付の有効範囲内である必要があります。
  - 年・月を足して存在しない日を月末にそろえ、日数を足した後、時間・分・秒・ミリ秒を経過時間として足します。`1d` は現地の暦で翌日の同じ時刻、`24h` は24時間後なので、夏時間をまたぐと結果が異なります。夏時間で飛ばされる時刻は時差の変更分だけずらし、2回ある時刻は1回目を使います。
  - 符号は次の符号まで引き継ぎます。`-1d 24h` は1日と24時間を引き、`-1d +24h` は1日を引いて24時間を足します。途中で日時の範囲を超えても、経過時間との相殺後が範囲内なら返します。たとえば UTC の上限に `1d -24h` を足すと元の時刻になります。範囲外の中間時刻の時差は、その範囲の端で得られる値を使います。
  - 有効範囲は UTC の `-271821-04-20T00:00:00.000Z` から `+275760-09-13T00:00:00.000Z` までです。たとえば `Asia/Tokyo` で `+275760-09-12T00:00:00.000Z` に `1d` を足すと、上限の日時になります。タイムゾーンで見た日付や時刻がこの表記を超えていても、実際の時刻が範囲内なら計算できます。
- **cron式の解説**の「式を組み立てる」では、何分ごと・毎時・毎日・毎週・毎月と時刻を選ぶと、今の形式の書き方で式を作ります。曜日は `MON` などの名前で書きます。形式によって日曜を 0 と数えるか 1 と数えるかが違っても、同じ曜日になるようにするためです。
- **cron式の解説**の夏時間の扱いは、飛ばされる時刻は実行せず、2回ある時刻は1回目だけ実行するものとして計算します。実際の動作は実装によって異なります。実行される日時が200年先まで見つからない式は「実行されない」と表示します。Spring の `@Scheduled` は Quartz に似ていますが、曜日の数字が異なる（日曜が 0）ため、曜日は `MON` などの名前で書いてください。
- Kubernetes の CronJob は形式で **Kubernetes** を選びます。
  - `5/15 * * * *` は毎時5・20・35・50分、`?` は `*` と同じです。
  - 曜日は0〜6（日〜土）で、7・逆順の範囲・`L`・`W`・`#` は受け付けません。
  - 日と曜日を両方絞った場合はORで扱い、`*/2` も絞り込みに含めます（標準形式の Linux cron と異なります）。
  - `@daily` などの定時マクロは使えますが、`@every` の経過時間指定には対応しません。
  - 式を読むタイムゾーンは `.spec.timeZone`（省略時はコントローラのタイムゾーン）に合わせてください。
