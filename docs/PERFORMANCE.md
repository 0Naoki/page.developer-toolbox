# 大容量処理の計測

[計測スクリプト](../scripts/measure-large-inputs.mjs) は、既定の9ツールに加え、オプションでサブネットの集約・重複チェックとパスワードの記号集合を計測できます。利用者向けの上限と制約は [USAGE.md](USAGE.md)、処理の構成は [ARCHITECTURE.md](ARCHITECTURE.md) を参照してください。

## 現在の計測方法

純粋関数と応答の複製を比較するスクリプトは、`scripts/benchmark.mjs` で読み込み・予備実行・3回の計測・記録を共通化しています。
比較元は開始時にコミットSHAへ固定します。比較方式は下の「比較元の選び方」で選びます。
記録の `provenance` は版ごとの入口・読み込んだソースのSHA-256・実行した生成コードのSHA-256です。
`snapshotFiles` は作業ツリーの依存・計測スクリプト・package-lockのSHA-256です。
途中でHEADや読み込んだ作業ツリーのファイルが変わった場合は、記録せずに再計測を求めます。
未コミット状態を後から復元するには、その変更も別途残す必要があります。

### 比較元の選び方

| 方式 | 比較元の読み込み | 選ぶ場面 |
|---|---|---|
| `--comparison=entry`（既定） | 入口だけ固定コミット、依存は両版で同じ作業ツリー | 依存をそろえ、入口の関数の変更だけを局所比較する |
| `--comparison=tree` | 入口とリポジトリ内の依存を固定コミットから読む | ファイル分割・依存の変更・依存ファイルの移動を含めて前後比較する |

対象は、エポック解析・パスワード生成・差分転送・文字診断のNode比較スクリプトです。
`--baseline=<コミットまたは参照>` で比較元を選びます。省略時は開始時のHEADです。

```powershell
node scripts/measure-epoch-parsing.mjs --comparison=tree --baseline=HEAD docs/records/epoch-tree-YYYY-MM-DD.json
node scripts/measure-epoch-parsing.mjs --comparison=entry --baseline=HEAD docs/records/epoch-entry-YYYY-MM-DD.json
```

tree方式は、現行で消えた依存ファイルもGitの内容から読みます。比較元にない依存を現行ファイルで代用しません。
比較する入口は、両版に同じパス・計測スクリプトが呼ぶAPIで存在する必要があります。
APIが変わった場合は、同じ入力と検証条件を満たす計測用の入口を用意してください。
作業ツリー・ブランチ・Gitの参照は変更しません。

外部パッケージは現行のインストールを共有するため、tree方式では両版のpackage-lockが一致しなければ停止します。
この方式は、異なる依存パッケージやNodeの版の比較には使いません。
計測前の依存の準備は、環境準備の手順に従ってください。
補助入口で測る通常集計や表示復元などは、引き続き作業ツリーだけの区間です。

記録の `comparison` に方式・固定した比較元SHA・結果内の比較元の名前を残します。
既定のentry方式の比較元は `HEAD`、tree方式や基準を明示した比較元は `baseline` です。
`dependencySource` に外部パッケージを共有する条件を残します。異なる方式の数値を同じ前後比較として混ぜないでください。

### ブラウザ計測の開始条件

```powershell
npm run build
node scripts/measure-large-inputs.mjs docs/records/performance-YYYY-MM-DD.json
```

Playwright の Chromium が必要です。未導入の場合は `npm run e2e:install` を実行してください。スクリプトは `127.0.0.1:4174` にローカルのプレビューサーバーを起動し、終了時に閉じます。

計測開始前に、E2Eと共通の `scripts/build-freshness.mjs` でビルドの更新を確認します。
対象と検査の限界は [TESTING.md の実行コマンド](TESTING.md#実行コマンド)を参照してください。
更新が必要なら、サーバーとブラウザを起動する前に停止し、`npm run build` を案内します。

各ケース（ツールと行数の組。行数は1,000・10,000・100,000）を3回測り、毎回新しいページを開きます。入力の更新直前から結果表示後の2フレームまでを測ります。入力はDOMの標準valueセッターとinputイベントで渡します。OSのクリップボード、キー入力の送信速度、Playwrightのfillに伴う待機の差を含めないためです。貼り付けイベントからの全文保持は別途E2Eで検証しています。

- JSON：大きな整数 `9007199254740993` と小数表記 `100.00`、日本語を含むレコードの配列。
- CSV：同じ値の行を項目名の行の後に並べる（CSV→JSON）。
- 文字数：`山田ABC123😀` を同じ行数だけ改行で連結。
- テキスト差分：番号付きの行を並べ、10行に1行だけ変えた2つのテキストを比べる。完了は「+N 行」の表示で判定する。
- Base64：`あいうえおabc` を同じ行数だけ改行で連結してエンコードする（10万単位を超えると Worker で変換）。
- ハッシュ生成は `あいうえおabc` を改行で連結し、SHA-256 の表示まで測ります。
- JWT は長い文字列をペイロードに含む合成トークンを使い、ペイロードの表示まで測ります。署名の検証は行いません。
- 証明書は行数の100分の1枚のテスト用 PEM を連結します。1,000行（10枚）は解析結果の表示まで、10,000行（100枚。PEM のブロック数の上限64を超える）と100,000行（入力の長さの上限を超える）は上限エラーの表示まで測ります。
- 正規表現は数字を含むテキストと数字の検索式を使います。1,000行はマッチ件数の表示まで、10,000行と100,000行（テスト文字列の上限10万単位を超える）は上限エラーの表示まで測ります。
- 終了状態：各ケースに期待する終了状態（`expected`。結果は `result`、エラーは `error`）を決めてあり、観測した状態を `outcome`（毎回の値は `runs[].outcome`）に記録します。期待と違う状態で終わったケースは失敗（`error: "UnexpectedOutcome"`）として記録します。
- 入力の形：結果には行数・全体の長さ（UTF-16単位）・行の見本とその長さを記録します。
- 集計：完了時間と最大描画間隔は、3回の中央値・最小・最大と、毎回の値（`runs`）を記録します。
- 完了時間：計算だけでなく、入力・結果の描画、150msの待機、Worker起動・転送、結果検出の時間も含みます。
- 最大描画間隔：計測中の `requestAnimationFrame` の最大間隔。CPU処理の時間そのものではなく、画面が更新されなかった時間の指標です。

### サブネットの集約・重複チェック

```powershell
npm run build
node scripts/measure-large-inputs.mjs --subnet docs/records/performance-YYYY-MM-DD-subnet.json
```

重複も隣接もしない合成IPv4アドレス10万件を使います。集約にはアドレスを、重複チェックには各行に `/32` を付けた入力を渡します。各ケースを3回実行し、完了時間と最大描画間隔を記録します。[過去の前後比較](records/PERFORMANCE.md#サブネットの集約重複チェック)では、追加の計測用コードでWorkerの計算・応答受信・描画を区間ごとに測っています。このコマンドで得られるのは現行ビルドの画面全体の計測値です。

### パスワード一括生成の準備処理

```powershell
node scripts/measure-password-generation.mjs docs/records/password-generation-YYYY-MM-DD.json
```

既存のビルドツールで計算処理をメモリ内へ読み込み、HEAD と作業ツリーを比較します。
HEAD の入口も依存ファイルは作業ツリーから読むため、依存を変えた比較では別のチェックアウトでも確認してください。
合成入力は `scripts/password-inputs.mjs` で作ります。入力の長さと、重複を除いた文字数を分けて記録します。

- 反復：同じ文字を1,000・100,000・1,000,000コードポイント並べます。候補は1種類です。
- 多種類：補助平面の異なるUnicodeスカラーを1,000・100,000コードポイント並べます。UTF-16単位では2倍です。
- 各入力の生成件数は1・5・20です。各組み合わせを予備実行後に3回測ります。
- 検証と生成計画の準備、準備済み計画からの生成、一括生成全体を分けます。計画APIのない版の個別区間は `null` です。
- 一括生成全体には準備も含まれるため、区間の時間を重ねて足しません。入力作成・描画・設定保存は除外します。

時刻・コミット・変更ファイル・ソースのハッシュ・環境・各回の時間と中央値を記録します。パスワード自体は記録しません。
小さなUnicode文字集合の全生成経路による条件と確率の検査は、単体テストで行います。

画面全体は、本番ビルドで次のコマンドを使います。

```powershell
npm run build
node scripts/measure-large-inputs.mjs --password docs/records/performance-YYYY-MM-DD-password.json
```

同じ5種類の合成入力を各3回測ります。使用する記号を変更する直前から、新しい生成結果と上限付きプレビューの描画後までです。
小さな入力はDOMのvalue更新、大きな入力は貼り付けイベントで渡します。全文の編集表示は開きません。
準備・生成・設定保存・描画を含む完了時間と最大描画間隔を記録し、Nodeの区間計測とは区別します。

### 文字診断の種類数と全件出力

```powershell
node scripts/measure-count-diagnostics.mjs docs/records/count-diagnostics-YYYY-MM-DD.json
npm run build
node scripts/measure-large-inputs.mjs --count-diagnostics docs/records/performance-YYYY-MM-DD-count-diagnostics.json
```

同じ絵文字の反復と、補助平面の異なるUnicodeスカラーを1,000・10,000・100,000コードポイント使います。
入力長と異なる文字数を分け、通常の表示用詳細は先頭分だけに保ちます。
各ケースを予備実行後に3回測り、Nodeでは次の区間を記録します。

- `counting`：文字数・バイト数と診断の集計を、HEADと作業ツリーで比較します。
- `intermediateBytes`・`retainedDetails`：集計関数の中間結果のV8サイズと詳細件数です。ピークヒープやWorker転送量ではありません。
- `normalMeasurement`：現行の行別測定と不可視検査を含む、通常の集計全体です。
- `fullReport`：操作時に行うShift_JIS診断の全件TSV生成です。通常の集計では実行しません。

区間には重複があるため合算しません。入力作成・DOM描画・クリップボード・保存はNode計測に含めません。
時刻・ソースのハッシュ・環境・各回の値を記録します。HEADの入口も依存は作業ツリーを使うため、その制約は共通の計測方法と同じです。

ブラウザは入力直前から通常集計の結果描画後までを各3回測り、完了時間と最大描画間隔を記録します。
全件出力の準備は選びません。大きな入力は貼り付けイベントで渡し、表示は上限内に保ちます。
全件出力のコピー・保存内容と、入力変更時の旧結果の無効化はE2Eで検査します。

#### 描画待ちの切り分け

```powershell
node scripts/measure-large-inputs.mjs --count-render-profile docs/records/count-render-YYYY-MM-DD.json
```

反復・多種類の10,000コードポイントを、通常表示・入力欄非表示・診断バッジ非表示・結果非表示で各3回測ります。
非表示は計測ページ内のCSSだけで行い、保持する入力と計算は変えません。非表示ケースは原因の切り分け用で、利用者向けの性能値には使いません。

| 計測点 | `runs` の項目 | 意味 |
|---|---|---|
| 入力イベントの同期処理 | `dispatchMs` | DOM更新とイベント発行の時間。後続のReact更新やレイアウトは含まない |
| Workerへ送信 | `workerPostedMs` | 入力直前から送信まで。150msの待機と、その前にメインスレッドが待たされた時間を含む |
| Worker応答の受信 | `workerReceivedMs` | 計算・起動・転送・イベント処理待ちを含む。Worker内計算だけの時間ではない |
| 結果DOMの更新 | `resultDomMs` | コードポイント数の表示をMutationObserverで検出した時点 |
| DOM更新後 | `domToEndMs` | 検出後の完了待ちと2フレームまで。レイアウト・描画だけを厳密に分離した値ではない |

時点の値は入力直前からの経過時間です。各項目の中央値を引き算して区間中央値にしないでください。
送信・受信の観測には計測ページだけでWorkerを包む処理を入れます。アプリのソースや安全設定は変更しません。

#### 改善を判断する基準

```powershell
node scripts/measure-large-inputs.mjs --count-budget docs/records/count-budget-YYYY-MM-DD.json
```

初期目標は、反復・多種類の各1,000・10,000・100,000コードポイントで、完了時間の中央値1,000ms以下、最大描画間隔の中央値250ms以下です。
3回とも新しいページを使い、同じブラウザ・OS・CPU・入力方法・ビルド条件で比較します。
画面は1280×720、deviceScaleFactorは1、言語はja-JPです。これらも記録に残します。
記録の `budget` が基準、各ケースの `budgetPassed` が判定です。期待と違う結果・計測失敗・目標超過は終了コード1にします。

これは今回の基準環境で、通常表示を改善するための目標です。全文編集や診断の文字の形の全表示は、利用者が選ぶ追加操作として別に測ります。
別の端末で比較する場合は、その環境の変更前後をそろえて記録してください。CIの一律の速度検査には組み込みません。
目標を変更する場合は、理由・比較環境・旧目標での結果も記録します。数値を超えた記録を消したり、入力条件を小さくして比較したりしません。

#### 全件出力のメモリ観測

```powershell
node --expose-gc scripts/measure-report-memory.mjs docs/records/report-memory-YYYY-MM-DD.json docs/records/report-memory-replay.json
```

最初の引数には、比較元の `sources.before` を含む既存の計測JSONを指定します。
初回の記録では、作業前に `reports.before.ts` と `issues.before.ts` を保存したディレクトリを指定します。元のソースは結果JSONにも含めます。

各試行の前にGCを実行し、集約直後・文字列化中・結合直後・上限拒否のチェックポイントで `heapUsed` を観測します。
1万・10万種類の成功ケースと、10万種類に200単位の小さい出力上限を与えた拒否ケースを各3回測ります。
チェックポイントの最大値と開始値との差を記録します。回収可能なごみも含む値で、観測間のピーク・RSS・ブラウザのメモリではありません。
観測用コードを生成コードへ挿入するため、処理時間の比較には使いません。観測位置・ソース・生成コードのハッシュも記録します。
変更前後の成功時は出力ハッシュ、拒否時はエラーが同じであることも確認します。

### 単一エポックの範囲外判定

```powershell
node scripts/measure-epoch-parsing.mjs docs/records/epoch-parsing-YYYY-MM-DD.json
```

HEAD と作業ツリーの解析処理を、各ケースの予備実行後に3回ずつ比較します。範囲外の数値は `9` を1,000・1,000,000・8,000,000単位並べたもの、有効な数値は `1` の先頭へ0、または `1.001` の末尾へ9を800万単位加えたものです。入力の単位は自動判定です。エラーとミリ秒の値が期待どおりかも確かめ、入力の準備・描画・保存を除く解析の時間だけを記録します。HEAD の入口も依存は作業ツリーから読むため、依存を変えた比較では別のチェックアウトでも確認してください。

### テキスト差分の応答

```powershell
node scripts/measure-diff-transfer.mjs docs/records/diff-transfer-YYYY-MM-DD.json
```

同一・中央1行変更は1,000・10,000・100,000行を使います。
全行変更・交互変更・長い行・改行主体は1,000・10,000行を使います。長い行は各行に「長い行」を100回足します。
各ケースを予備実行後に3回測り、次の値を別々に記録します。

| 項目 | 含む処理 | 含まない処理 |
|---|---|---|
| 計算全体 | 差分探索・全文パッチ・応答の構築 | 入力の準備・結果の正しさの検証 |
| 応答形式の選択と構築 | 本文量・行数の概算、入力参照または行の直接保持の構築 | 差分探索・全文パッチ |
| 応答の複製 | NodeのstructuredClone | Workerの起動・ブラウザの通信 |
| 表示行の復元 | 折りたたみ・先頭1,000行の左右表示と統合表示の作成 | React・DOMの描画 |
| データ量 | V8のシリアライズサイズと行オブジェクト／範囲数 | 実際のヒープ使用量 |

変更前後で、差分から両方の入力を復元できることを確認します。
両方の探索が完了した場合は全文パッチの一致も確認します。打ち切り時には最短パッチの一致を要求しません。
計算全体には圧縮も含むため、これらの時間を重ねて足さないでください。
応答形式は転送量の概算で選びます。すべての入力・実行環境で最小サイズになる保証はありません。

ブラウザ全体の完了時間と描画間隔は、同じビルドで次のコマンドを使います。

```powershell
npm run build
node scripts/measure-large-inputs.mjs --diff docs/records/performance-YYYY-MM-DD-diff.json
```

既存の差分ケースを1,000・10,000・100,000行、各3回測ります。
ブラウザの結果とNodeの区間計測は別の指標として比較してください。

## 記録の残し方

計測コマンドと、使用したビルドを作ったコマンドを記録してください。未コミットの計測用変更を使った場合は、対象コミットに加えて変更箇所と計測点を記載し、再現用のコミットや計測コードがあれば参照を添えてください。

変更前後で同じ環境・入力を使い、生データ（スクリプトが保存する JSON）を `docs/records/` に残し、[記録の一覧](records/PERFORMANCE.md#記録の一覧) に1行追加してください。

- 測定日時（`measuredAt`）、対象コミットSHA（`commit`）、未コミット変更の有無（`uncommittedChanges`）、配信した `dist` の内容のハッシュ（`build.distSha256`）、OS・CPU・メモリ・Node.js・ブラウザ、各ケースの実行回数（`runsPerCase`）は、スクリプトが自動で記録します。
- 比較に並列数や入力の変更が含まれる場合は、その違いを明記します。未測定の環境への効果は断定しません。

試行ごとに `dist` を照合し直し、計測中に変わったら計測を止めます。そのときの記録は `invalid` と `build.changedDuring` が付き、値は比較に使えません。

`commit` は計測した時点の `HEAD` で、`dist` をビルドしたときのコミットとは限りません。測ったビルドが `commit` のものかを確かめるには、そのコミットで `npm run build` をやり直し、次のコマンドで表示したハッシュを `build.distSha256` と比べます（同じソースからのビルドは同じハッシュになります）。

```powershell
node scripts/measure-large-inputs.mjs --dist-hash
```

`--dist-hash` は成果物のハッシュだけを表示し、計測しません。過去の成果物も調べられるよう、更新時刻の検査は行いません。
